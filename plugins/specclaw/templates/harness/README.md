# {{title}} — Golden-Master Capture Harness

Generated by `/specclaw:bf-baseline --harness`. This project captures golden-master fixtures for the scenarios documented in `.specclaw/baseline/scenarios.md` — **it does not run itself; a human runs it.**

## What this is

- References `{{core_project_path}}` directly — never the UI project(s).
- One xUnit `[Fact]` per scenario (`GM-NNN`), arranging state via a real database (same pattern as `{{existing_test_project}}`), then writing a fixture JSON file via `FixtureWriter` — the fact does not need to assert pass/fail; capturing the fixture *is* the point.
- Every fixture records its own capture timestamp, an anchor date, the legacy repo's commit SHA, and the runtime version, so `/specclaw:bf-baseline --record` can build a manifest and a human can judge whether a later replay diverged for a real reason or an environment/timing reason.

## Commands

```bash
cd {{harness_relative_path}}
dotnet build
dotnet test
```

Fixtures land in `{{fixtures_relative_path}}`, one file per scenario ID. After running, go back to the project root and run:

```
/specclaw:bf-baseline --record
```

to validate the captured fixtures against `scenarios.md` and produce `.specclaw/baseline/manifest.json`.

## Extending to other stacks

This generator currently targets **.NET only** (detected via `codebase-report.md`'s Tech Stack section). To extend `/specclaw:bf-baseline --harness` to another stack, the extension point is `agents/bf-baseline-designer.md`'s **Mode: harness** section — add a stack-detection branch there and a matching scaffold under `templates/harness/` for that ecosystem's test/capture-project conventions. Nothing in `bin/specclaw-bf-baseline` or the scenario-derivation logic in Mode A is .NET-specific; only the harness code generator is.
