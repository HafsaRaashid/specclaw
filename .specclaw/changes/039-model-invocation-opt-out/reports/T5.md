# T5 — L2: deterministic report rendering for bf-quality

`bin/specclaw-bf-quality-render` (new, 295 lines) and the `bf-quality` skill branch. Commit
`8621688`, exactly two files, +317/−1. No stray artifacts left in the working tree.

The renderer reads `quality.json` / `quality-target.json` / `quality-delta.json` per `--mode`,
pastes the three `report_blocks.*_md` fields verbatim between their anchors (byte-identical copy of
`substitute()` from the collector, and of `yaml_val`/`project_title` from `specclaw-build`, per the
repo's duplication convention), fills the literal artifact facts, replaces every narrated section
with the marker, strips the template's HTML instruction comments, and fails loudly naming the field
and its producing command when a `report_blocks` field is missing.

The skill's Step 2 reads `bf.narration` via `yaml_val` and checks ARGUMENTS for `--no-model`. Only
the literal `false` (or the token) takes the deterministic path; `off`, `no`, `0`, empty, a typo and
an absent key all leave the spawn exactly as it was, stated in the skill with the reason. Nothing
forces narration back on against `bf.narration: false`. The deterministic branch falls through to
the existing lint step unchanged and tells the user the report was rendered, not written.

**Orchestrator's independent verification**, in a scratch repo built from three real `bin/` scripts,
rendered and compared field-by-field rather than trusting the agent's report.

**Pre-existing defect found while verifying (NOT introduced here, and in a file this branch does not
touch):** `specclaw-bf-quality-collect:3250` reads the QI registry as
`known_qis="$(grep -oE '^### QI-[0-9]+' "$reg" | ... )"` with no `|| true` — line 3256 has one. When
the registry exists but holds zero `### QI-` entries, that grep exits 1 and `set -euo pipefail`
aborts `lint-report` **silently**, rc=1, no message. Isolated below: the same report and artifact
lint clean the moment one QI heading exists. `git diff main...HEAD` for that script is empty, so this
is main's behaviour, reached by this change only because it is the first thing to lint a report on a
zero-hotspot repo. Reported to the operator; not fixed here.
