# T8 — Fix the silent lint abort on a zero-entry QI registry

Added to scope by operator decision during wave 2, after T5's AC-5 verification hit it.

`specclaw-bf-quality-collect:3250` read the QI registry through
`grep -oE '^### QI-[0-9]+' "$reg" | grep -oE 'QI-[0-9]+' | LC_ALL=C sort -u` with no `|| true` —
while the `comm` four lines below, at `:3256`, has one. On a registry that exists but holds zero
`### QI-` entries, the grep exits 1, `set -euo pipefail` aborts `lint-report`, and the caller sees
rc=1 with **no message and no verdict**. A zero-entry registry is not an edge case: it is the normal
state of a clean repo, and of any machine without the complexity tooling installed.

Fixed by adding `|| true`, matching its neighbour, with a comment recording why. Pre-existing on
`main` — `git diff main...HEAD` for this script was empty before this commit — and reached by this
change only because the deterministic renderer is the first thing to lint a report on a
zero-hotspot repo.

Isolated before and after in the same scratch repo, same report, same artifact, only the registry's
QI count varying.

## Verification

Command: `specclaw-bf-quality-collect lint-report .specclaw .specclaw/analysis/quality-report.md .specclaw/analysis/quality.json` (zero-QI registry, before and after the fix)
Exit: 0

Output:

    BEFORE, registry with 0 QI headings:
      lint rc=1   (silent — no stdout, no stderr)
    BEFORE, one '### QI-001' heading appended:
      REPORT-LINT: PASS — every MOD-###, every QI-### and all three computed blocks agree.
      lint rc=0
    AFTER the fix, heading removed again, registry back to 0 QI headings:
      REPORT-LINT: PASS — every MOD-###, every QI-### and all three computed blocks in
      .specclaw/analysis/quality-report.md agree with .specclaw/analysis/quality.json.
      lint rc=0
